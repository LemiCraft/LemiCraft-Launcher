# Выпуск версий

Версии собирает и публикует GitHub Actions. Запуск делается кнопкой, а описание и публикация остаются ручными шагами: пока релиз не опубликован, его не видят ни сайт, ни Discord, ни лаунчеры игроков

## Как это устроено

Workflow [`release.yml`](.github/workflows/release.yml) запускается кнопкой «Run workflow» и делает следующее:

1. Берёт версию из `src-tauri/Cargo.toml` и отказывается работать, если релиз с такой версией уже опубликован
2. Создаёт **черновик** релиза: заголовок равен тегу `vX.Y.Z`, в описании шаблон «Что нового» и ссылка `Full Changelog` на сравнение с предыдущим тегом
3. Параллельно собирает Windows, Linux и macOS (универсальная сборка для Intel и Apple Silicon) и загружает файлы в черновик под именами, которые ожидает сайт
4. Подписывает файлы обновления для Linux и macOS и добавляет в черновик `latest.json`: по нему лаунчер находит обновление и проверяет его подлинность
5. Собирает Flatpak из готового `.deb` и тоже кладёт его в черновик

Отдельный workflow [`build.yml`](.github/workflows/build.yml) запускается вручную и собирает все платформы без релиза, это проверочная сборка

## Что нужно заранее

- Права на запись в репозиторий и на создание тегов (теги защищены правилом репозитория)
- Два секрета Actions (Settings, Secrets and variables, Actions):
  - `TAURI_SIGNING_PRIVATE_KEY`: содержимое файла приватного ключа
  - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: пароль от него

Локальная сборка (`npm run tauri build`) ключ не требует

## Порядок выпуска

1. **Версия.** Номер задаётся одной строкой `version` в `src-tauri/Cargo.toml`, в других файлах его менять не нужно. Туда же добавляется строка `<release version="X.Y.Z" date="ГГГГ-ММ-ДД"/>` в `packaging/flatpak/ru.lemicraft.Launcher.metainfo.xml`. Изменения коммитятся в `main`
2. **Запуск.** Вкладка Actions, workflow «Release», «Run workflow» на ветке `main`. Тег `vX.Y.Z` создаётся автоматически при публикации черновика
3. **Сборка.** Занимает около 30 минут, ход виден на вкладке Actions, workflow «Release»
4. **Описание.** В черновике на странице Releases слово `ЗАПОЛНИТЬ` заменяется пунктами «Что нового», по одному `- ...` на строку. Если оставить шаблон, это слово попадёт в окно обновления у игроков
5. **Проверка файлов.** В черновике должны быть все файлы из таблицы ниже
6. **Публикация.** Кнопка **Publish release**. После неё сайт подхватывает версию, в Discord приходит уведомление, лаунчеры начинают предлагать обновление

Файлы опубликованного релиза заменять нельзя: sha256, по которому Windows проверяет обновление, берётся с GitHub и привязан к конкретному файлу

## Файлы релиза

| Платформа | Файлы |
|---|---|
| Windows | `-installer.exe`, `-portable.exe` |
| Linux | `-amd64.deb`, `-x86_64.rpm`, `-x86_64.AppImage`, `.flatpak` |
| macOS | `-macos-universal.dmg`, `-macos-universal.app.tar.gz` |
| Обновление | `latest.json` |

Имена начинаются с `LemiCraft-Launcher-X.Y.Z`. Сайт определяет платформу по имени файла, поэтому имена менять нельзя

## Образ macOS

Внешний вид окна `.dmg` задан в `src-tauri/tauri.macos.conf.json` (размер окна и позиции значков), файлы лежат в `packaging/macos/`:

- `background.tiff`: фон 660×400, в одном файле два размера, обычный и для Retina
- `VolumeIcon.icns`: значок диска, который появляется после открытия образа

Tauri ставит диску иконку приложения, поэтому значок диска подменяет скрипт `set-volume-icon.sh` уже после сборки. Расстановку значков по окну делает Finder через AppleScript, ради этого в workflow включена переменная `TAURI_BUNDLER_DMG_IGNORE_CI`

## Ключ подписи обновлений

Автообновление на Linux (AppImage) и macOS проверяет подпись скачанного файла публичным ключом, который зашит в лаунчер (`plugins.updater.pubkey` в `src-tauri/tauri.conf.json`). Файл с другой подписью не устанавливается. Windows обновляется отдельным путём, по sha256 с сайта, и ключ ему не нужен

- Приватный ключ и пароль в репозиторий не попадают и хранятся у мейнтейнера отдельно друг от друга
- Секрет в GitHub прочитать обратно нельзя, поэтому он не заменяет резервную копию
- При потере ключа новые обновления для Linux и macOS подписать нечем. Нужно сгенерировать новый ключ (`npx tauri signer generate`), обновить публичный ключ в конфиге и секреты, выпустить версию. Установленные лаунчеры её сами не получат, её нужно один раз скачать вручную

## Если что-то пошло не так

| Ситуация | Что делать |
|---|---|
| Ошибка «release already published» | Релиз с такой версией уже опубликован, нужно поднять версию в `Cargo.toml` |
| Сборка упала до загрузки файлов | Исправить причину, удалить черновик, запустить workflow заново |
| Упала одна платформа | В Actions выбрать «Re-run failed jobs»: файлы дозагрузятся в тот же черновик |
| Не создался `latest.json` | Он собирается только после успешных сборок всех платформ, перезапустить упавшие |
| Сборка macOS падает или зависает на шаге dmg | Finder на сервере не справился с оформлением окна. Убрать `TAURI_BUNDLER_DMG_IGNORE_CI` из `release.yml` и `build.yml`: образ соберётся без фона и расстановки значков, остальное не пострадает |

Удаление тега:

```
git push origin :refs/tags/vX.Y.Z
git tag -d vX.Y.Z
```
